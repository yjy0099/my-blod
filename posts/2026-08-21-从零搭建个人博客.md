## 需求其实很简单

我想要的东西不多：

- 用 Markdown 写文章，写完丢进文件夹就能发
- 能按分类、标签、归档翻文章
- 打开要快，最好没有白屏
- 十年之后这个项目还能打开，不用重装依赖

按这个清单去对，会发现大部分框架都"超纲"了。

## 三个候选方案的对比

| 方案 | 优点 | 我放弃的理由 |
| --- | --- | --- |
| Next.js | 生态强、图片优化、SSR | 需要 Node 环境，升级一次依赖可能就跑不起来 |
| Hugo | 构建极快、主题多 | 要装二进制，模板语法又是一套新东西 |
| 纯静态 + Markdown | 零依赖、零构建 | 需要自己写解析和路由，代码量稍大 |

前两个的问题不是不好，而是**维护成本发生在未来**。三年后我想改个样式，得先回忆一遍当年的构建链路。

## 最终架构

```text
posts/*.md  →  build_index.py  →  posts/index.json  →  前端渲染
```

只有加文章这一步需要跑脚本，其余全是静态文件。浏览器直接读 Markdown 原文，前端解析成 HTML。

> 判断标准只有一条：如果五年后我没法在十分钟内让它跑起来，那这个方案就是错的。

## 我做了哪些取舍

放弃了站内全文搜索——文章数量在百篇以内时，侧边栏的标签和归档已经够用。等真的搜不动了，再加也不迟，无非是多一个 `search.js`。

放弃了评论系统——Giscus 这类方案要挂 GitHub 账号，不如先专注把内容写好。
